Making a Big Four firm’s template editor about 60% faster on large templates

Consultants at a Big Four advisory firm build long, deeply nested templates. The bigger the template, the slower the editor became. I rebuilt how templates load and are cached, and large templates now open about 60% faster.

The problem

The platform lets advisory teams build structured templates: sections, subsections and questions, with reusable content blocks and rules that show or hide parts of a template. Templates in real use are long and deeply nested.

Opening a large template meant fetching and drawing the whole hierarchy before the author could start work. Editing felt heavy, and the problem grew with every section added. For a tool people use all day, that wait was the most visible issue.

What made it hard

  • Two views of one structure. A drag-and-drop canvas and a tree view had to stay in sync while only part of the data was loaded.
  • Rules across the hierarchy. The rule engine references questions in other sections, so partial loading could not break rule evaluation.
  • No disruption. Authors were using the platform throughout; changes had to ship without a freeze or data migration risk.

What I built

  • Incremental retrieval. APIs return one level of the hierarchy at a time instead of the whole template, so the first screen needs only a fraction of the data.
  • Multi-level lazy loading. The Angular editor loads subsections and questions as the author expands or scrolls to them, in both the canvas and the tree view.
  • Redis caching. Frequently opened templates and reusable content blocks are served from Redis instead of rebuilt from SQL Server on every request.
  • Full editing workflow. Create, copy, update, delete and reorder across all levels, with drag and drop on the canvas mirrored in the tree, plus comments and standalone view modes.
  • Cloud integration. Azure Functions for background workflows, Key Vault for secrets and Blob Storage for files.

How it fits together

  1. Angular 19 editorCanvas and tree view, loading only what is on screen
  2. .NET 8 APIsReturn one level of the hierarchy at a time
  3. Redis cacheServes frequently opened templates without hitting SQL
  4. SQL ServerStores the template hierarchy and reusable blocks
  5. Azure FunctionsRun heavy background work outside the request

The result

  • About 60% faster loading for large templates, measured on the client’s own templates.
  • The editor stays responsive as templates grow, because the work done on open no longer scales with template size.
  • Lower database load on busy days, since repeat opens are served from cache.
